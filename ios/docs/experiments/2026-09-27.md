# Mobile recommendations and cross-app simulator speed — September 27, 2026

## Result

Thimvale's current simulator inference adapter was slower than the two comparator builds on all three small models in this study. PocketPal delivered the highest median streaming rate; LLMFarm generally had lower time to the first token. The host was busy, and the adapters retain meaningful implementation differences, so these are exploratory observations, not a controlled iPhone or App Store ranking.

Separately, the picker now recommends models by use case, based on the current [Artificial Analysis mobile leaderboard](https://artificialanalysis.ai/hardware-inference-stack/mobile-phones) and official model cards. The balanced pick is LFM2.5-2.6B, with a lighter LFM2.5-1.2B-Instruct default for lower-memory phones. MiniCPM5-1B, Qwen3.5 4B, Nanbeige4.2-3B, and Ling 3.0 Tiny cover other tradeoffs. The [recommendation review](../model-recommendations.md) explains the evidence and limitations. Published phone measurements are not mixed into the simulator results below.

## What was measured

- Release **source builds**: Thimvale's real `PMInference` adapter, PocketPal 1.18.0's real `llama.rn` streaming API, and LLMFarm 1.6.0's real Swift inference adapter. Competitors have test-only entry points; decoding kernels were not changed or upgraded.
- Apple M4 Mac, 24 GiB RAM, 10 logical CPUs, macOS 26.5.1; arm64 iPhone 17 Pro simulator on iOS 26.1 / Xcode 26.1.1. The simulator profile does not turn the Mac into an iPhone processor.
- Identical checksummed GGUF files and user prompt; per-model prompt token counts agree across apps. Six generation threads, 4,096 context, temperature zero, 128 emitted tokens, fresh model context for each repetition, prefix caching disabled.
- One excluded warmup plus four measured repetitions per app/model. Rate = 127 intervals divided by time between the first and last streamed callbacks. Load and first-token latency are separate. This is API-level delivery, not normal chat rendering or a bare kernel benchmark.
- Builds finished before accepted timings. Other development servers, browser automation, and simulators continued running; approximately 17 GiB of host swap was occupied. The study did not stop other people's workloads or flush OS caches.

Source revisions, framework hashes, host conditions, and rejected pilots are in [environment.json](2026-09-27/environment.json). The [reproduction guide](2026-09-27/REPRODUCE.md) includes patches, configuration differences, token-counter validation, and model hashes.

Measured app order: Thimvale, LLMFarm, PocketPal. Each app ran Gemma, Qwen, then Liquid. Ranges show all four measured repetitions, not confidence intervals.

| Gemma 3 1B / Q4_K_M | Thimvale | 8.4 | 7.1–9.1 | 12.40 s | 0.92 s |
| | PocketPal | 17.6 | 11.9–18.4 | 7.39 s | 0.49 s |
| | LLMFarm | 12.0 | 11.3–12.7 | 5.22 s | 0.32 s |
| Qwen3 0.6B / Q8_0 | Thimvale | 7.1 | 5.9–7.9 | 6.28 s | 1.26 s |

The PocketPal versus LLMFarm Liquid medians are effectively a tie given the wide ranges. PocketPal's faster stream does not imply it always produces the first token sooner. Model loads are warm-file-cache reloads, not cold storage performance; ordinary Thimvale chats keep selected weights resident until backgrounding/inactivity or memory pressure.

## Thimvale repeat after the competitors

Without changing the binary or settings, Thimvale ran the complete matrix again after PocketPal had exited. Both its initial XCTest run and this repeat passed. The repeat is preserved rather than substituted for the first pass.

| Model | First-pass median tokens/sec | Repeat median tokens/sec | Repeat range | Repeat first token |
| --- | ---: | ---: | ---: | ---: |
| Gemma 3 1B Q4_K_M | 8.4 | 9.2 | 8.0–9.4 | 9.61 s |
| Qwen3 0.6B Q8_0 | 7.1 | 9.7 | 9.1–10.0 | 5.57 s |
| LFM2.5 230M Q4_K_M | 22.0 | 34.3 | 30.2–37.1 | 3.99 s |

Thimvale remains behind the competitor medians, but its Liquid median changes by approximately 56% with **no code change**. This is strong reason not to promote the first-pass ratios as stable speedups. Across all four app runs there are 48 measured generations and 12 excluded warmups, all with the required prompt/output counts. Competitors were not rerun in the repeat block; [summary-repeat.json](2026-09-27/summary-repeat.json) reuses their original samples explicitly.

## Configuration and interpretation limits

1. These are not installed App Store binaries. iOS device apps cannot simply be installed as simulator builds. [PocketPal](https://github.com/a-ghorbani/pocketpal-ai) and [LLMFarm](https://github.com/guinmoon/LLMFarm) were chosen because their app source and real inference adapters could be built and instrumented. Closed-source apps such as [Private LLM](https://privatellm.app/models/best-for-iphone) were not measured. No claim is made about all leading apps or their download/popularity ranking.
2. No physical-iPhone Metal, battery, thermal endurance, multimodal, retrieval, tool-use, answer-quality, or UI-rendering benchmark was run. Apple's [performance guidance](https://developer.apple.com/documentation/xcode/improving-your-app-s-performance) emphasizes profiling on devices; simulator results are not device-performance predictions.
3. The work was not a randomized, isolated-host study. Load changed over time. Numeric ratios are descriptive, not established causal speedups, and no significance test is claimed.
4. All three use zero model GPU layers/CPU-configured execution. PocketPal additionally excludes GPU devices; Thimvale still registers the simulator Metal backend. LLMFarm uses its repository's prebuilt CPU framework. This does not establish identical backend scheduling or compiler flags.
5. Thimvale and PocketPal use 256/128 native batch/microbatch sizes. LLMFarm evaluates 256-token input chunks through an older native context whose defaults are 2,048/512 and whose batch-thread setting is not exposed. Its zero-temperature sampler also ignores the exposed repeat-penalty setting; Thimvale and PocketPal apply 1.1 over 64 tokens. Generated text can differ. No competitor engine was rewritten to force equality.
6. The existing adapters produce matching duplicated BOS tokens for Gemma/Liquid. Counts are Gemma 244, Qwen 234, Liquid 229. This preserves current runtime behavior for comparison, but it is not a validation of ideal chat formatting. Fixing BOS handling should be a separate correctness experiment, with new baselines.
7. PocketPal's pinned native counter excludes the first sample: 127 native predicted tokens correspond to 128 emitted tokens. The reporter checks all raw streaming events, final text, limit-stop status, and counters before normalizing. LLMFarm's count comes from its per-token callbacks. See the guide for the exact checks and Unicode limitations.

## Engineering lead, not an optimization claim

The existing Thimvale universal simulator library was generated with `GGML_CPU_GENERIC` in the `ggml-cpu` Release target, with `GGML_NATIVE=OFF` and both arm64/x86_64 selected. The pinned engine's `ggml/src/ggml-cpu/arch-fallback.h` selects generic quantized dot-product implementations under that flag. This is a concrete candidate for the observed gap, particularly Qwen Q8, but the experiment did not isolate it causally.

The next useful test is an A/B rebuild of the **simulator slice only**, selecting the proper ARM backend, with identical samplers, exact prompt token IDs, randomized app/model order, and a quiet host. Then repeat on a physical iPhone using the shipping Metal path. No production inference settings were changed and no speed improvement is claimed by this recommendation update.

## Verification

The Release simulator app compiled, both recommendation integration tests passed, and the picker UI test passed with visible role switching and expandable benchmark evidence. The final UI run used a freshly installed test runner after an earlier runner-cache mismatch; the earlier attempts are not evidence for the final assertions. Core tests: 13 passed. Release/report tests: 29 passed. The strict reporter validated all completed study files, and both comparator patches passed reverse-apply checks against their instrumented source trees. The experiment remains opt-in and is skipped by normal CI.

The iOS recommendation UI changed; Android receives the shared snapshot asset but no new recommendation UI in this change. Catalog file availability was checked for all 40 entries; that is not a claim that 40 models completed inference. The default recommendation does not change the user's selected model or start a download.
