# Simulator experiments: inference and grounded answers

These are development experiments, not independent model rankings or iPhone performance claims. All inference ran in the native iOS app's test host on the iPhone 17 Pro simulator (iOS 26.1), using CPU inference on an Apple M4 Mac with 24 GB of memory. Simulator Metal offload is disabled. Model loading is excluded from generation timings.

## Reproduction

From `ios/`:

```sh
bash scripts/fetch-test-assets.sh
bash scripts/fetch-experiment-assets.sh
bash scripts/run-experiments.sh retrieval
bash scripts/run-experiments.sh inference
bash scripts/run-experiments.sh cache
bash scripts/run-experiments.sh answers
bash scripts/run-experiments.sh files
# Optional batch-size trial; no change to production batch defaults:
bash scripts/run-experiments.sh batches
```

Do not run other CPU-heavy tests during timing experiments. `THIMVALE_SIMULATOR_ID` can override the selected simulator. The separate `ThimvaleExperiments` scheme opts into long-running tests; ordinary CI skips them and never downloads the extra experiment models. All fixtures are synthetic or the existing checksummed Wikipedia knots pack. Experiment output is never enabled for customer conversations.

The fetch scripts pin revisions and verify SHA-256. Models: Liquid LFM2.5 230M Q4_K_M, official Qwen3 0.6B Q8_0, and Gemma3 1B Q4_K_M. Different quantizations make cross-model speed rankings inappropriate. The point is a within-model comparison.

## Changes under test

- Retain exact decoded token prefixes in the existing model context. Append-only turns can reuse hybrid/recurrent state; edits require supported rollback. A mismatch, discarded sliding-window history, cancellation, failed decode, or unloading invalidates reuse. No prompt cache is written to disk.
- Request output logits only for the final prompt batch. Intermediate batches still update model state.
- Keep the existing compressed text, binary vectors, and FTS index. Rerank a bounded shortlist using full-precision sentence embeddings in memory, with one embedding of the query. Repeated questions do not earn lexical answer-relevance points, and duplicate passages are reduced.
- Give models bounded, verbatim query-focused windows. Do not further cut already-short passages: doing so initially lost an answer phrased as “taller” when the query said “height.” The source inspector retains the original indexed passage. Tool-using prompts retain source paths; answer-only prompts omit path clutter.
- Expand Wikipedia candidate discovery with bounded phrase searches over metadata and title-aware ranking. Preserve leading full-text candidates for descriptive questions, then decompress only the chosen articles. Rank local files and Wikipedia together instead of placing every local hit ahead of every Wikipedia hit.
- Make the answer-only prompt distinguish an absent fact or a different subject from genuine evidence, while keeping sources untrusted and tools unavailable in that response.

The [pinned llama.cpp API](https://github.com/ggml-org/llama.cpp/blob/b10830/include/llama.h) documents partial-rollback failures, retained memory ranges, and partially processed aborted batches. Those constraints are why cache reuse must have a correctness fallback. No experimental KV quantization, recurrent snapshots, GPU settings, or larger production batches were enabled.

## Retrieval results

The hand-built stress corpus has 10 fictional project facts, long repetitive introductions, and 10 distractor documents that repeat questions without answering them. All fixtures were inspected during development. Odd/even labels are reporting partitions, not a blind holdout; early raw logs used “tuning/holdout” labels, which should not be interpreted as an independent evaluation.

| Measure | Original | Revised |
| --- | ---: | ---: |
| Answer-bearing passage ranked first | 0/10 | 10/10 |
| Mean reciprocal rank | 0.328 | 1.000 |
| Answer retained in model evidence | 10/10 | 10/10 |

Reranking costs roughly a tenth of a second for this small corpus versus a few milliseconds for the original search. The benefit is less irrelevant model context, not faster database lookup. This is not a test of a 20,000-passage library.

The original normalized full-text queries missed “Sheet bend” and “Reef knot” from their first six hits. The revised path finds Sheet bend first and both Granny knot and Reef knot in its top three for their comparison. Additional checks cover Clove hitch, Carrick bend, Figure-eight knot, Knot theory, and a descriptive query whose answer is in an article body rather than its title. The latter initially failed: generic matching titles displaced the relevant body match. Candidate ranking now also uses distinctive words in archive search snippets, without decompressing every candidate. These checks use real archived articles, not mocked search results.

## Imported iPhone files

`LocalFileKnowledgeTests` creates actual files in the simulator app's Documents directory, then calls `KnowledgeService.importURL`, not the direct in-memory text importer. The seven files cover nested Markdown folders with identical filenames, UTF-8 text, CSV, JSON, HTML with navigation/script distractors, and a two-page selectable-text PDF. The resulting eight document/page records are persisted in SQLite and searched through a newly opened service.

All seven factual queries retrieved their answer-bearing file first. Checks verify that focused evidence retains the fact, citations retain the actual file path and PDF page, hidden files/unsupported files/symlinks are excluded, re-import is idempotent, edits replace old indexed facts, and deleting one source does not delete an identically named file in another folder. Mixed local-file/Wikipedia searches and the Work tool's independent knowledge permission are also regression tests. A UI test opens the imported radio field notes and its citation inspector after relaunch.

The separate three-model file-answer trial uses those same real imported files, a two-file comparison, and a missing-price question. Expected phrases appeared in 2/7 single-file Liquid answers, 3/7 Qwen answers, and 7/7 Gemma answers. **These are not accuracy scores**: Gemma incorrectly described the current Aster code as invalid, and weaker outputs included filenames/citation numbers without answers. All three models included both facts in the two-file question, but only Qwen cited both supporting files. Qwen and Gemma declined the missing-price question; Liquid produced a source list instead.

These new file cases expose limits not apparent from Qwen's 10/10 phrase score on the earlier direct-index corpus. They were not removed or tuned away. This is precisely why file imports are tested separately. The tests exercise local iOS storage and the production URL importer; they do not test iCloud hydration or a third-party Files provider's security-scoped access on a physical phone.

## Answer results and limitations

Each model used the same 10 factual questions at temperature 0.6 with the simulator's fixed seed, plus an empty-evidence question and two unanswerable questions with distractors. This is one sample per factual question, not a multi-seed accuracy study.

| Model | Expected phrase present, original | Revised | Phrase present plus any supporting source cited, original → revised |
| --- | ---: | ---: | ---: |
| Liquid 230M | 2/10 | 8/10 | 2/10 → 6/10 |
| Qwen 0.6B | 10/10 | 10/10 | 10/10 → 10/10 |
| Gemma 1B | 3/10 | 5/10 | 0/10 → 5/10 |

These permissive automatic measures are deliberately **not called accuracy**. An answer can contain the expected phrase while adding a false claim. A citation somewhere in an answer is not proof that every claim is correctly attributed. For example, an original Gemma answer added Thursday to a source that only said Tuesday. Liquid still sometimes returns source lists instead of answering or adds unrelated facts. Raw generated answers are included in the result files for inspection.

Qwen's original answer to a nonexistent Pelican depot question copied the Cedar observatory's access code. The revised answer declines that question. An earlier candidate also incorrectly declined three answerable Qwen questions; that candidate was rejected, and the ranking was revised before the final answer pass.

Median input tokens decreased from approximately 1,100–1,200 to approximately 400–450 in the final answer trial. Background emulator/build activity began during that trial, so absolute between-run timing differences are confounded by host load. Use paired cache measurements for the speed comparison; do not extrapolate these timings to an iPhone GPU.

## Speed experiments

The initial thread sweep used 2, 4, and 6 threads, three runs each, discarding the first for timing summaries. Six threads beat two and four for all three models in this simulator. The existing thread default was therefore retained. No blanket “fewer threads is faster” change was made.

Three paired trials per model alternated cached/fresh order and required byte-for-byte equal greedy output. Follow-up prompts shared 580–623 tokens with the preceding turn. Median time to first token:

| Model | Fresh prefill | Reused prefix |
| --- | ---: | ---: |
| Liquid 230M | 11.52 s | 0.48 s |
| Qwen 0.6B | 15.97 s | 1.04 s |
| Gemma 1B | 26.85 s | 1.29 s |

All nine cached/fresh output comparisons passed. This is a reduction in repeated **prefill work**, not a claimed 15–24× increase in token decoding speed. There were only three pairs, host load varied, and these are simulator CPU results. Unrelated prompts or invalidated state may require a full prefill. The raw-throughput sweep supports retaining the existing six-thread setting, not claiming a newly demonstrated raw decoding improvement.

A separate three-model check also passed all 12 greedy comparisons for changed and repeated short prompts. The normal real-model regression checks cancellation, an over-context error, release/reload, and recovery against a fresh engine. Existing residency tests still cover release after inactivity and reloading on the next request.

The cache measurement testcase passed in a run whose separate descriptive Wikipedia test failed. The raw export explicitly retains `overall_test_run_succeeded: false` and scopes records to the passing cache testcase. The Wikipedia bug was subsequently fixed and its focused regression rerun passed. Successful measurements are not used to conceal that earlier failure.

## Regression verification

The normal simulator run passed 46 native tests and 21 UI tests, with seven opt-in long experiment methods skipped. Its remaining Work UI testcase failed two timing assertions: a short real response had already completed before the test looked for the temporary streaming view. Visual inspection confirmed the complete answer and inline citation. The test now accepts either a live response or a completed response, while keeping its answer, citation, approval, and disclosure assertions. A separate deliberately long generation still requires the live streaming UI. This correction changes the test, not app behavior.

The repaired Work case, long-response streaming/release case, and imported-file citation/relaunch case each passed twice in the targeted verification run: six executions, zero failures. Together with the earlier unchanged cases this verifies all 46 native and 22 UI regression tests; the initial full-run failure is retained, not relabeled as success. Core checks: 13 passed. Release/report checks: 23 passed. Unsigned Release iPhone compilation passed; the built app retains the exempt-encryption declaration and contains no experiment model/archive assets or simulator fixture switches. Actionlint, shell syntax, catalog consistency, and whitespace checks passed. Physical-device performance remains untested.
